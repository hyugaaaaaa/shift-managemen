# システム開発・運用ガイドライン

## 1. はじめに
本ドキュメントは、アルバイトシフト管理・給与計算システムの開発および運用におけるルールと手順を定めたものです。
開発者および運用管理者は、本ガイドラインに従ってシステムの品質維持・向上に努めてください。

## 2. 開発ガイドライン

### 2.1 コーディング規約
システム全体の統一性と可読性を保つため、以下の規約を遵守してください。

*   **PHP**: PSR-12 (Basic Coding Standard) に準拠します。
    *   インデントはスペース4つを使用する。
    *   クラス名は `PascalCase`、メソッド名は `camelCase`、変数名は `snake_case` とする。
    *   `Strict types` (`declare(strict_types=1);`) の導入を推奨する（新規ファイル）。
*   **HTML**: セマンティックなマークアップを心がける。
    *   インデントはスペース2つまたは4つ（プロジェクト内で統一）。
    *   IDやクラス名はケバブケース (`main-content`) を使用する。
*   **CSS**:
    *   Bootstrapのユーティリティクラスを優先して使用し、独自のCSS記述を減らす。
    *   独自スタイルは `css/style.css` に記述し、HTML内に `style="..."` で直書きしない（動的な値を除く）。
*   **Security (必須)**:
    *   **XSS対策**: 出力時には必ずヘルパー関数 `h($str)` を使用してエスケープする。
    *   **SQLインジェクション対策**: データベース操作は必ずプリペアドステートメントを使用する。
    *   **CSRF対策**: フォーム送信（POST）には必ず `generate_csrf_token()` でトークンを埋め込み、受信側で検証する。

### 2.2 ディレクトリ構成ルール (MVC)
本システムは簡易的なMVCアーキテクチャを採用しています。ファイルの配置場所を間違えないようにしてください。

*   `~/` (ルート): コントローラー (Controller)
    *   リクエストの受け付け、データ処理、ビューの呼び出しを行うファイル。
*   `~/views/`: ビュー (View)
    *   HTMLの表示のみを担当するファイル。ロジックは最小限にする。
    *   ファイル名は `xxx_view.php` とする。
*   `~/src/`: クラス・モデル
    *   ビジネスロジックやDB操作を行うクラスファイル。
*   `~/docs/`: ドキュメント
    *   設計書、マニュアル、本ガイドライン等。

### 2.3 Git運用ルール
*   **コミットメッセージ**:
    *   日本語で簡潔に記述する。
    *   プレフィックス推奨: `[Add] 新機能`, `[Fix] バグ修正`, `[Update] 変更`, `[Docs] ドキュメント`
*   **.gitignore**:
    *   機密情報を含むファイル (`.env`) や、自動生成されるファイル (`vendor/`) は絶対にコミットしない。

## 3. 運用ガイドライン

### 3.1 環境構築・更新
本システムは Composer を使用してライブラリ管理を行っています。

*   **初期セットアップ**:
    ```bash
    composer install
    copy .env.example .env
    # .env 内のDB設定等を環境に合わせて編集
    ```
*   **ライブラリの追加・更新**:
    ```bash
    composer require [パッケージ名]
    # または
    composer update
    ```
    ※ `vendor/` ディレクトリは手動で変更せず、必ずComposer経由で管理すること。

### 3.2 データベース管理
*   **スキーマ変更**:
    *   テーブル定義の変更を行う際は、必ず `db/schema.sql` にも変更内容を反映させること。
    *   すでに運用中のDBへの変更手順（ALTER文など）をコメントとして残すか、マイグレーションスクリプトを作成すること。

### 3.3 バックアップ運用
データ損失に備え、以下のバックアップを定期的に取得することを強く推奨します。

*   **データベース**: `mysqldump` コマンド等による日次バックアップ。
*   **設定ファイル**: `.env` やカスタマイズした設定ファイルのバックアップ。

### 3.4 定期実行タスク (Cron/タスクスケジューラ)
*   **メール送信キュー処理**:
    *   スクリプト: `process_mail.php`
    *   推奨頻度: 毎分 (1分おき)
    *   設定方法: Windowsタスクスケジューラにて `php.exe` から上記スクリプトを実行するよう登録。

### 3.5 ログ・トラブルシューティング
*   **エラーログ**:
    *   PHPのエラーログ（`php_error_log`）を確認する。XAMPPの場合は `xampp/php/logs/php_error_log` 等にある。
*   **デバッグモード**:
    *   `.env` ファイルの `APP_DEBUG` を `true` にすると詳細なエラーが表示されるが、**本番環境では必ず `false` に設定すること**。

## 4. ドキュメント管理

### 4.1 更新ルール
システムに変更を加えた場合は、必ず対応するドキュメントも更新すること。

*   **システム概要書**: 機能追加、アーキテクチャ変更時。
*   **要件定義書**: 仕様変更、機能追加・削除時。
*   **本ガイドライン**: 運用ルールの変更時。
