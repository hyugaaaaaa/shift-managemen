# レスポンシブデザイン計画書

## 1. 目的
本システムをスマートフォン（SP）やタブレット端末からでもストレスなく操作できるようにする。
特に、アルバイト従業員が自身のスマホから「希望シフト提出」や「確定シフト確認」を行うシーンを最優先とする。

## 2. 対応範囲
- **対象デバイス**: スマートフォン (幅375px〜), タブレット (幅768px〜), PC (幅1024px〜)
- **対象ブラウザ**: Chrome, Safari (iOS), Edge の最新版

## 3. 基本方針
- **Bootstrap 5の活用**: 既存のBootstrapグリッドシステム (`col-md-*` 等) を最大限活用する。
- **Mobile First**: スマホ表示を基準とし、必要に応じてPC向けのスタイルを拡張する（またはその逆の既存CSSを調整）。
- **可読性の確保**: スマホ利用時はフォントサイズを16px以上に保ち、タップ領域を十分に確保する（44px以上推奨）。

## 4. 画面別対応方針

### 共通レイアウト (Header/Footer)
- **ナビゲーション**: ハンバーガーメニュー (`navbar-toggler`) を使用。展開時のメニュー項目間の余白を広げる。
- **コンテナ**: 画面幅の狭いデバイスでは左右パディングを `15px` 程度に縮小し、有効領域を広げる。

### 希望シフト提出画面 (FullCalendar)
- **カレンダー**: 
  - ツールバー: `prev,next` ボタンと `title` を簡素化。
  - ビュー: 月表示 (`dayGridMonth`) を維持するが、セルの高さを自動調整 (`height: auto`)。
  - イベント: スマホでは「●」などのドット表示にするか、文字サイズを小さくして溢れないようにする。

### ダッシュボード (カレンダー)
- **PC**: 従来通りのテーブルカレンダー。
- **SP**: 1日1行のリスト形式、または縦積みカード形式に変更し、スクロールで見られるようにする（既存の `.mobile-shift-list` をブラッシュアップ）。

### 各種一覧・管理画面
- **テーブル**: `table-responsive` を適用し、横スクロールで対応。
- **操作ボタン**: 画面下部に固定フローティングアクションボタン (FAB) の導入は今回は行わず、各行または上部配置で対応。

## 5. UI/UX改善案
- **入力フォーム**: `input[type="date"]` や `input[type="time"]` はOSネイティブのピッカーが起動するようにする（現状でOK）。
- **モーダル**: スマホ時は画面下部からのスライドアップ（Bottom Sheet風）ではなく、中央配置のまま幅を90%〜100%にする。
