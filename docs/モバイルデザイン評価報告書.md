# モバイルデザイン評価と改善提案書

## 1. 現状の評価

現在のコードベース（`style.css`, `template.php`, `submit_shift_view.php`）を分析した結果、基本的なレスポンシブ対応は完了しており、一定のモダンなデザイン品質が確保されています。

### 良い点 (Good)
*   **レスポンシブ基盤**: Bootstrap 5をベースに、`viewport`設定やグリッドシステムが正しく機能しています。
*   **配色と統一感**: `style.css` で変数を活用し、一貫したカラーパレット（青基調）とスペーシングが適用されています。
*   **主要コンポーネントの調整**:
    *   カレンダー（CMS）に対して、モバイル用（768px以下）のスタイル調整（ツールバーの折り返し、フォントサイズ縮小、タップ領域の確保）が既に行われています。
    *   ボタン類は「Pill形状（丸角）」でタップしやすいデザインになっています。

### コンテンツごとの課題 (Issues)
*   **カレンダーの視認性**:
    *   月表示（Month View）をモバイル画面に縮小表示しているため、1日あたりの表示領域が狭く、イベント（シフト）名が読みづらい可能性があります。
    *   `min-height: 60px` でタップ領域は確保されていますが、情報量が多い日は視認性が低下します。
*   **ナビゲーション**:
    *   現在の上部ハンバーガーメニューは標準的ですが、頻繁に利用する「シフト提出」や「確認」へのアクセスとしては、スマホアプリライクな「下部固定タブバー」の方が片手操作に適しています。
*   **フォーム入力**:
    *   一部のフォントサイズ調整が入っていますが、入力要素が16px未満の場合、iOSで自動ズームが発生する可能性があります（現状のCSSを見る限り概ね大丈夫そうですが確認が必要です）。

## 2. 改善提案

モバイル体験を「Webサイト」から「アプリ」レベルに引き上げるための改善案を提案します。

### 優先度: 高 (High)

#### ① カレンダーのモバイル最適化 (List Viewへの切り替え)
スマホ画面では、無理に月間カレンダー（グリッド）を表示するのではなく、**リスト表示（List View）** に切り替えることを推奨します。
*   **PC**: 従来の月間カレンダー（全体俯瞰重視）
*   **SP**: `listMonth` またはカスタムリストビュー（情報可読性重視）
*   **実装イメージ**: FullCalendarの `windowResize` または初期化オプションで、画面幅に応じて `initialView` を切り替えます。

#### ② ボトムナビゲーションの導入
スマホ閲覧時のみ、画面下部に固定のアイコンメニュー（タブバー）を表示します。
*   **項目例**: [ホーム] [シフト提出] [確定シフト] [設定]
*   これにより、ハンバーガーメニューを開く手間なく主要機能にアクセスできます。

### 優先度: 中 (Medium)

#### ③ タップフィードバックの強化
スマホアプリのような操作感触を出すために、タップ時のアニメーション（Ripple effect等）や、カードのタッチ時の沈み込み演出（現状も一部ありますが）を全体に統一します。

#### ④ iOS対応微調整
*   セーフエリア（`padding-bottom: env(safe-area-inset-bottom)`）への対応（特にボトムナビ導入時）。
*   入力フォームのフォントサイズを16px以上に固定し、ズーム防止。
