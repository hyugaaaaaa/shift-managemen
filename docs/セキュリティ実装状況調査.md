# セキュリティ対策実装状況レポート

ユーザーより提示された5つの脆弱性対策について、現在のコードベースの実装状況を確認しました。

## 1. SQLインジェクション
**対策の基本:** ユーザー入力をSQL文に直接連結しない。プリペアドステートメントを使用する。
**現状:** **[実装済み]**
- `PDO` クラスを使用したプリペアドステートメントが `src/Services/ShiftService.php`, `src/Models/`, 各種コントローラー (`register_company.php`等) で徹底されています。
- バッチ処理 (`db/` 配下のスクリプト) やユーザー入力を含まない固定クエリでは一部 `query()` が使用されていますが、セキュリティ上の問題はありません。

## 2. クロスサイトスクリプティング (XSS)
**対策の基本:** ユーザー入力をHTMLとして出力する際に無害化する（エスケープ）。
**現状:** **[実装済み]**
- `functions.php` に定義されたヘルパー関数 `h()` (`htmlspecialchars` のラッパー) が用意されています。
- `views/` フォルダ内の各テンプレートファイルで、変数出力時に `<?php echo h($var); ?>` や `htmlspecialchars()` が適切に使用されています。

## 3. クロスサイトリクエストフォージェリ (CSRF)
**対策の基本:** 正当なフォームからの送信であることを確認する (CSRFトークン)。
**現状:** **[実装済み]**
- `src/Security/Csrf.php` クラスによりトークンの生成と検証ロジックが実装されています。
- ログイン、登録、設定変更などのフォーム全てに `csrf_token` hiddenフィールドが含まれており、POST送信時に `validate_csrf_token()` 関数で検証されています。

## 4. セッションハイジャック
**対策の基本:** セッションIDの固定化を防ぐ。Cookieに属性を付与する。
**現状:** **[概ね実装済み]**
- **ID再生成:** `index.php` (ログイン処理) および `views/login_view.php` の処理フロー内で `session_regenerate_id(true)` が呼び出されており、ログイン成功時にセッションIDが切り替わります。
- **Cookie属性:** `config.php` にて以下の設定が確認できました。
    - `session.cookie_httponly`: 1 (有効)
    - `session.use_strict_mode`: 1 (有効)
    - `session.cookie_secure`: HTTPS接続時に自動的に有効化
    - `SameSite` 属性: 明示的な設定はありません（PHPのバージョン依存のデフォルト動作になります）。明示的に `Lax` または `Strict` を設定することでより強化可能です。

## 5. ファイル操作の脆弱性
**対策の基本:** ファイル名やパスにユーザー入力を直接使わない。MIMEタイプチェック。
**現状:** **[該当なし]**
- 現在のコードベース (`functions.php`, `src/Services/`, `owner/`, `parttime/`) を調査しましたが、ユーザーがファイルをアップロードする機能（`move_uploaded_file`, `$_FILES` の使用）は見当たりませんでした。
- したがって、現時点ではファイルアップロードに伴う脆弱性のリスクはありません。今後機能を追加する際は対策が必要です。

---
**結論:** 提示された5項目のうち、該当機能がない「ファイル操作」を除き、重要なセキュリティ対策は適切に実装されています。
